# ProfPay — контекст для ИИ-агента

Учёт плательщиков профсоюзных взносов СПбГУПТД. Работает на VDS `profpay.site`,
пользуется один бухгалтер профкома. ~300 записей, рост до ~1000.

**FastAPI + PostgreSQL 15 + React 18 (Vite, Radix Themes), Docker Compose.**

---

## Правила работы с этим проектом

Код и комментарии — **по-русски**, включая docstring'и и сообщения интерфейса.
Комментарий объясняет **почему**, а не что: «иначе двойное шифрование», а не
«шифруем поле». Если правило неочевидно или на нём уже обжигались — это стоит
записать рядом с кодом.

**Текст в интерфейсе — короткий.** Подписи, а не объяснения. Было «Последний
курс. С 1 сентября такие записи уходят в архив сами — скажите по каждому…» →
стало «С 1 сентября уходят в архив». Длинные пояснения раздражают.

**Проверять на данных, а не на словах.** Есть боевая выгрузка из Excel на 302
человека — прогон на ней ловит то, чего не видно в тестах. Миграции и
разрушительные операции обкатываются на копии базы до продакшена.

Тесты: `pytest backend/tests -q` (161 шт., должны быть зелёными).
Сборка фронта: `npm --prefix frontend run build` (включает `tsc`).

## Доменные правила

Это главное. Нарушение любого из них — баг, даже если код выглядит корректно.

### Курс не хранится

В базе лежит **`admission_year`** (год поступления), курс считается на лету:

```
курс = начало текущего учебного года − год поступления + 1
```

Учебный год начинается 1 сентября. Все переходят на курс выше сами, без
фоновых задач. Вся логика — [`backend/domain/academic.py`](backend/domain/academic.py).

Срок обучения задаёт уровень: **бакалавриат 4, специалитет 5, магистратура 2**.
Когда срок вышел — запись уходит в архив: остаётся в базе с историей платежей,
но пропадает из списков, должников и статистики.

Первая цифра кода группы — это и есть курс. «1-мд-35» на третьем курсе
показывается как «3-мд-35», в базе остаётся исходная строка. Буквы группы
хранятся **строчными** — иначе «1-МД-7» и «1-мд-7» станут разными группами.

### Бюджетник ≠ платник

Взнос бюджетника удерживает из стипендии бухгалтерия вуза. **Профком этих денег
не получает.** Отсюда:

- бюджетник числится оплаченным всё время, пока состоит в профкоме;
- **платежей ему не заводят** — в «Собрано средств» попадают только настоящие деньги;
- должником он быть не может: это условие в SQL (`paying_clause`), а не только
  в статусе записи.

Статистика считает **участников** целиком, потом делит на бюджет и платников.
Деньги и долги — только по платникам. Проценты считаются от платников: «147
должников из 305» — бессмыслица, если 158 из этих 305 бюджетники.

`stipend_amount` и `budget_percent` в карточке — **справка**, ни на что не влияют.
Сумма взноса берётся из `PaymentSettings` («Настройки» → «Оплата»).

Статус приводится к правилу при старте приложения (`_sync_budget_status`):
записи, залитые из Excel, про него не знают. Освобождённых (`EXEMPT`) не трогает.

### Архив

`is_archived` = срок обучения вышел **или** проставлен `archived_at`.

`archived_at` — явная отметка ухода: отчислился, доучился, вышел из профкома.
Ставится с главной, из блока «Скоро закончат обучение». Обратима.

### Шифрование — частичное

Зашифрованы Fernet'ом только опасные при утечке дампа поля: **контакты, дата
рождения, примечания, номера квитанций**. ФИО, группа, кафедра, курс и суммы
лежат открытыми — по ним идут поиск, сортировка и подсчёт **в SQL**.

Ключ — в `ENCRYPTION_KEY`, не в базе. Раньше он заворачивался в пароль
пользователя, и второй пользователь при первом входе получал свой ключ,
переставая читать чужие записи.

**Порядок при правке записи принципиален:** расшифровать всё → наложить
изменения → зашифровать всё. Иначе нетронутые поля получают второй слой
шифрования и становятся нечитаемыми. В `encrypt_field` есть защита от повторного
шифрования, но полагаться только на неё нельзя.

## Устройство

| Каталог | Что там |
|---|---|
| `backend/domain/` | Модели и учебный календарь. Свойства `computed_course`, `is_archived`, `is_final_year`, `missing_fields` |
| `backend/application/` | Схемы Pydantic — валидация входа и формат ответов |
| `backend/infrastructure/` | Репозитории. Все фильтры и агрегаты — в SQL |
| `backend/presentation/` | Ручки API под `/api/v1`: `/auth/*`, `/stats/*`, остальное без префикса |
| `backend/tools/` | Скрипты: импорт из Excel, миграции, аварийный сброс доступа |
| `frontend/src/` | React SPA на Radix Themes |

**Условия в SQL** (`repositories.py`) — их дублируют свойства модели, и если они
разойдутся, интерфейс начнёт врать. На каждое есть тест, сверяющий пару:

- `graduated_clause` ↔ `Payer.is_archived`
- `final_year_clause` ↔ `Payer.is_final_year`
- `incomplete_clause` ↔ `Payer.missing_fields`
- `paying_clause` — кто платит сам

**Репозитории отдают расшифрованные объекты, отцепленные от сессии**
(`_safe_expunge`), иначе расшифровка улетит обратно в базу.

## Вход и безопасность

- Пароли — bcrypt с предварительным SHA-256 (снимает предел 72 байта, из-за
  которого длинный русский пароль молча обрезался).
- 5 неудачных попыток → блокировка на 15 минут. Счётчик в базе, не в памяти.
- **Второй фактор (TOTP) обязателен для всех по умолчанию** и заводится под
  каждую учётную запись отдельно. Пока приложение не привязано, рабочие разделы
  закрыты — проверка в `require_role`, то есть на сервере. `/auth/*` остаётся
  открытым, иначе привязаться было бы негде.
- Администратор без привязанного приложения может снять требование прямо с
  экрана привязки: настройки закрыты тем же требованием, иначе выходила бы
  запертая дверь с ключом внутри.
- Резервные коды показываются один раз; экран не уходит, пока их не подтвердят.
  Потерянный набор перевыпускается под пароль и код.
- QR-код рисует сервер (`segno`) **самостоятельным SVG с `xmlns`**. Без него
  браузер не открывает картинку по `data:`-адресу — на месте кода была пустота,
  и привязаться можно было только вводом ключа руками.
- Выгрузка в Excel обезвреживает значения, начинающиеся с `=`, `+`, `-`, `@`.
- `X-Forwarded-For` принимается только от прокси из локальной сети.

## Оформление

Radix Themes: акцент `grass`, серый `sage`, `radius="large"`, `scaling="95%"`.
Светлая и тёмная темы, переключатель в шапке.

**Сброс Tailwind выключен** (`preflight: false`) — он перебивал фон кнопок Radix.
Вместо него минимальный свой сброс в `index.css`. Палитра Tailwind указывает на
токены Radix (`bg-red-50` → `var(--red-2)`), поэтому старые классы следуют теме.

Грабли со специфичностью, на которых уже обожглись: селектор
`button, [type="submit"]` весит как класс и перебивает и кнопки Radix, и утилиты
Tailwind. Сброс кнопок держится **одним селектором по тегу**.

Прежний плоский вид доступен в «Настройках» → «Классическое», стили грузятся
отдельным куском по требованию.

### Тяжёлая графика

Три компонента вендорены из [React Bits](https://reactbits.dev) **как есть** —
обновляются заменой файла целиком, редактировать их не надо:

| Файл | Что | Обёртка |
|---|---|---|
| `AeroShards.jsx` | фон входа на WebGPU (`vgpu`) | `LoginBackground.tsx` |
| `AnimatedContent.jsx` | появление при прокрутке (`gsap`) | `Reveal.tsx` |
| `BorderGlow.jsx` | свечение карточки под курсором | `GlowCard.tsx` |

Обёртки решают **одно и то же**: подставить цвета темы вместо палитры по
умолчанию и не включать это в классическом оформлении и при
`prefers-reduced-motion`. Всё грузится отдельными кусками сборки.

Фон стоит ровно на двух экранах — вход и обязательная привязка. Дальше его нет:
за таблицами сидят часами.

**Прокручивается `<main id="app-scroll">`, а не окно.** ScrollTrigger по
умолчанию слушает окно и не сработал бы никогда — блоки остались бы невидимыми.
`Reveal` проверяет наличие этого элемента и без него просто не анимирует.

## Импорт из Excel

`python -m backend.tools.import_payers файл.xlsx` — сначала вхолостую, потом
`--apply`. Колонки ищутся по названиям, порядок неважен. Одной транзакцией;
повторный запуск не задваивает (совпадение по ФИО).

Не угадывает: неразобранная группа или неправдоподобная дата (Excel подставляет
текущий год) оставляют поле пустым и попадают в отчёт. Записи с пробелами потом
находятся пунктом «Неполные данные» в «Плательщиках».

Курс больше срока обучения → уровень поднимается автоматически: пятикурсник не
бывает на четырёхлетней программе, иначе он ушёл бы в архив в момент загрузки.

## Развёртывание

`docker-compose.prod.yml`, порт `127.0.0.1:${PROFPAY_PORT:-8020}`, SSL и лимиты
на host nginx. Подробности и runbook'и — [deploy.md](deploy.md).

**Код бэкенда вкомпилирован в образ** (`COPY backend/`), тома с исходниками нет:
после `git pull` нужна пересборка, иначе в контейнере останется старый код.

Списки в `.env` (`CORS_ORIGINS`, `TRUSTED_HOSTS`) принимаются через запятую и в
JSON. `CORS_ORIGINS=*` приложение отвергает: вместе с куками сессии это даёт
любому сайту слать запросы от имени вошедшего.

Приложение падает на старте с внятным сообщением, если настройка неверна, —
это намеренно: лучше не стартовать, чем писать данные не тем ключом.
