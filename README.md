# ProfPay

Учёт плательщиков профсоюзных взносов СПбГУПТД. FastAPI + PostgreSQL + React.

- Запуск и деплой: **[deploy.md](deploy.md)**

## Как устроено

| Каталог | Что там |
|---|---|
| `backend/domain/` | Модели и учебный календарь (`academic.py`) |
| `backend/application/` | Схемы Pydantic — валидация входа и формат ответов |
| `backend/infrastructure/` | Репозитории; шифрование полей прозрачно для вызывающего |
| `backend/presentation/` | Ручки API |
| `backend/tools/` | Разовые скрипты: миграция шифрования, аварийный сброс доступа |
| `backend/tests/` | Тесты (`pytest backend/tests`) |
| `frontend/src/` | React SPA на Radix Themes |

## Шифрование

Зашифрованы только те поля, которые опасны при утечке дампа: **контакты,
дата рождения, примечания, номера квитанций**. ФИО, группа, кафедра, курс
и все суммы лежат открытыми — по ним идут поиск, сортировка и подсчёт в SQL.

Это осознанный размен. Когда зашифровано было всё, список из двадцати человек
поднимал из базы всю таблицу со всеми платежами и расшифровывал каждое поле
в Python; на тысяче записей так работать нельзя.

Ключ задаётся переменной `ENCRYPTION_KEY` и живёт в окружении, а не в базе.
Прежняя схема заворачивала ключ в пароль пользователя — из-за этого второй
пользователь при первом входе получал собственный ключ и переставал читать
чужие записи.

Модель угроз: защищаемся от утечки дампа или файла бэкапа. От полного доступа
к серверу это не защитит — держите `.env` и бэкапы раздельно.

## Курс и архив

Курс не хранится. В базе лежит **год поступления**, курс считается на лету:

```
курс = начало текущего учебного года − год поступления + 1
```

Учебный год начинается 1 сентября, поэтому все переходят на курс выше сами,
без фоновых задач, которые могут не сработать или сработать дважды. Первая
цифра кода группы — это и есть курс: «1-мд-35» на третьем курсе показывается
как «3-мд-35», а в базе остаётся исходная строка.

Группа вводится по частям — курс, буквы, номер, — а год поступления выводится
из курса и текущей даты и правится вручную, если человек перевёлся или был
в академе.

Срок обучения задаётся уровнем: бакалавриат 4 года, специалитет 5,
магистратура 2. Когда срок вышел, запись уходит в архив — остаётся в базе
со всей историей платежей, но пропадает из списка, из должников и из
статистики. Открыть: «Остальное» → «Архив выпускников».

Вся логика в [`backend/domain/academic.py`](backend/domain/academic.py).

## Защита входа

- Пароли — bcrypt с предварительным SHA-256 (снимает предел в 72 байта,
  из-за которого длинный русский пароль обрезался).
- 5 неудачных попыток → блокировка учётной записи на 15 минут.
- Отдельный лимит по IP в host nginx на `/auth/login`.
- Второй фактор — приложение-аутентификатор (TOTP, RFC 6238): Google
  Authenticator, Aegis и подобные. Секрет и резервные коды в базе зашифрованы,
  подбор кода упирается в ту же блокировку, что и подбор пароля.
- Второй фактор обязателен для всех по умолчанию и заводится под каждую
  учётную запись отдельно. Пока приложение не привязано, рабочие разделы
  закрыты — проверка стоит в зависимости `require_role`, то есть на сервере,
  а не только в интерфейсе. Требование снимается в «Настройках».
- Смена пароля тоже подтверждается кодом: иначе чужая открытая сессия
  позволила бы сменить пароль в обход второго фактора. Перебор кода вне входа
  ограничен отдельным счётчиком — там блокировка учётной записи не работает.
- Резервные коды показываются один раз, и экран не уходит, пока их не
  подтвердят; потерянный набор перевыпускается под пароль и код. Без этого
  обязательный фактор был бы ловушкой: отключить его нельзя, а запасного
  входа уже нет.
- Слабые пароли отсекаются по списку частых, а не требованиями к составу:
  от «обязательно спецсимвол» люди пишут «Пароль1!» и клеят на монитор.
- `X-Forwarded-For` принимается только от прокси из локальной сети — иначе
  лимит по IP обходился бы подстановкой нового адреса в каждом запросе.
- Выгрузка в Excel обезвреживает значения, начинающиеся с `=`, `+`, `-`, `@`:
  примечание вида `=HYPERLINK(...)` иначе стало бы формулой у того, кто
  открывает файл.
- Все действия пишутся в журнал: «Остальное» → «Журнал изменений».

Восстановления по почте нет намеренно — SMTP-сервер для этого не нужен.
Что делать при потере доступа, описано в [deploy.md](deploy.md#второй-фактор-входа).

## Оформление

Интерфейс собран на [Radix Themes](https://www.radix-ui.com/themes): акцент
`grass`, серый `sage`, скругления `large`. Светлая и тёмная темы переключаются
кнопкой в шапке, выбор («светлая / тёмная / как в системе») сохраняется
в браузере.

Палитра Tailwind указывает не на конкретные цвета, а на токены Radix
(`--accent-9`, `--gray-12`), поэтому классы вида `bg-light` следуют теме сами.
Базовый сброс Tailwind выключен: его правило для `<button>` перебивает фон
кнопок Radix — вместо него в `index.css` минимальный собственный сброс.

Прежний плоский вид остался доступен: «Настройки» → «Оформление» →
«Классическое». Его стили вынесены в отдельный файл и подгружаются только
при выборе.

Шрифты и иконки локальные, внешних CDN нет — Content-Security-Policy
остаётся с `font-src 'self'`.

Анимированный фон — [AeroShards](https://reactbits.dev) из React Bits,
рисуется на WebGPU. Компонент лежит в `frontend/src/components/AeroShards.jsx`
как есть и обновляется заменой файла целиком. Подключён он через
`LoginBackground.tsx`, который грузит его отдельным куском сборки и только
там, где WebGPU есть и не включено «уменьшить движение»; иначе остаётся
спокойный градиент.

Фон стоит ровно на двух экранах — вход и обязательная привязка приложения.
Оба — до того, как человек попал внутрь системы. В рабочих разделах его нет:
за таблицами взносов сидят часами, и движущаяся картинка под ними мешала бы
читать. Содержимое на обоих экранах лежит на матовом стекле
(`backdrop-filter`), цвета берутся из темы, поэтому оно читается и на светлой.

  pytest backend/tests -q
